# OCR 工作台滚动布局设计

- 日期：2026-08-25
- 范围：`apps/demo` 单 SDK Demo 的桌面端工作区布局
- 状态：用户已确认方案，待实现

## 问题

右侧模型信息、运行环境、耗时和缓存区域与 OCR 结果列表叠加后，内容高度超过首屏。当前工作区只有最小高度，右栏允许把网格继续撑高，因此浏览器滚动整页时中间图片会一起离开视口；OCR 列表也只能在首屏底部显示少量结果。

## 设计

桌面端工作区使用固定视口高度 `calc(100vh - 顶部栏高度)`，并设置 `min-height: 0` 与 `overflow: hidden`，阻止右栏内容撑高页面。左侧控制栏和右侧详情栏各自拥有垂直滚动；中间图片区保持工作区高度，图片内部继续使用现有的缩放、拖动和滚轮隔离逻辑。

右侧详情栏保持现有信息顺序，并拆成“信息摘要区”和“OCR 结果区”两个垂直区域。摘要区内部可滚动，OCR 区占据右栏约一半高度并独立滚动，不再使用固定 `420px` 高度。这样模型信息仍然可访问，同时首屏能显示更多 OCR 行；滚动结果不会移动中间图片。

平板和移动端继续使用现有的响应式堆叠顺序：平板详情区位于工作区下方并可自然展开；移动端图片区和 OCR 列表保留足够的固定阅读高度，避免桌面端规则压缩移动布局。

## 验证

- Playwright 桌面测试确认工作区高度等于视口减去顶部栏、页面不产生垂直滚动、详情栏自身可滚动、图片顶部位置在详情栏滚动前后不变。
- 现有 OCR 识别、图片缩放/拖动、移动端无横向溢出测试继续通过。
